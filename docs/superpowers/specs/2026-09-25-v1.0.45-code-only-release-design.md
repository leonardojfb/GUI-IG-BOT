# v1.0.45 Code-Only Release Design

## Goal

Publish the current application changes as private release v1.0.45 without
shipping any developer or client runtime data.

## Included product surface

The package uses the existing explicit `build_release.ps1` release-file list.
It therefore includes the changed desktop application modules for Forge
iPhone, partial Forge/Logistica, captions, Telegram, rendering, and updating.

## Excluded data

The package must not include `organizador.db`, database backups, generated
media, `CALENDARIO_POSTEO`, `calendar_manifest.json`, caption working files,
history, caches, or local build artifacts. Existing installer data must remain
untouched on upgrade.

## Release flow

1. Change `version.json` to `1.0.45` and regenerate both release manifests
   through `build_release.ps1`.
2. Run the focused regression suite for the included changed product areas,
   compile the changed Python modules, and check the diff.
3. Inspect the ZIP contents and its SHA-256 to prove runtime data is absent.
4. Commit only releaseable source, tests, version and manifest changes; do not
   stage local runtime/data artifacts.
5. Push the active branch and create private GitHub release `v1.0.45` with the
   generated ZIP and manifest.

## Failure handling

If validation or release publication fails, preserve the local working tree,
report the exact failing command, and do not claim the release was published.
